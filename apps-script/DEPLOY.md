# SmashStats 同期ブリッジ — デプロイ手順

共通Apps Script（Webアプリ）をデプロイして、PWAとユーザーのスプレッドシートをつなぐ。
デプロイ作業自体はブラウザで実施する。ここでは手順だけを書く。

## 前提

- デプロイするGoogleアカウント（＝ブリッジ用アカウント）が1つ必要。
  このアカウントでスクリプトが実行される（Execute as: USER_DEPLOYING）。
- **大事な注意**: スクリプトはデプロイしたアカウントの権限で動くため、
  各ユーザーのスプレッドシートは **ブリッジ用アカウントと「編集者」として共有**
  しておく必要がある。共有を外せば同期は止まる（端末内とシート内のデータは残る）。
  共有されていないシートを開こうとすると、ブリッジは `SPREADSHEET_NOT_SHARED`
  を返す。
- スプレッドシートの中身はブリッジには保存しない。ブリッジが持つのは
  各スプレッドシートIDに紐づいた合言葉のハッシュ（`BIND_<ID>`）だけ。
  合言葉そのものは保存しない。
- 合言葉はユーザーごとに違う。各ユーザーが初回接続時に自分で決める。
  初回 init でそのスプレッドシートIDと合言葉のハッシュが紐づき、
  以後は同じ合言葉でなければ読み書きできない。他のユーザーが
  スプレッドシートIDを知っていても合言葉なしでは触れない。
  **デプロイ担当は、他のユーザーのスプレッドシートを共有で開ける立場に
  あること自体は変わらない**（Apps Script はデプロイしたアカウントの
  権限で動くため）。共有を外せば同期は止まる。

## 1. プロジェクトを作る

1. https://script.google.com/ を開く（ブリッジ用アカウントでログイン）。
2. 「新しいプロジェクト」を作成する。
3. エディタの `コード.gs` の中身をすべて消し、`Code.gs` の内容を貼り付ける。
4. 左の「プロジェクトの設定」（歯車）→「エディタ」の設定ではなく、
   エディタ左端のファイル一覧の `appsscript.json` を開く。
   表示されない場合は、プロジェクトの設定 →「appsscript.json マニフェスト ファイルを
   エディタで表示する」にチェックを入れてから開く。
   `appsscript.json` の内容をこのフォルダのものに置き換える。
   （`webapp.executeAs: USER_DEPLOYING`、`webapp.access: ANYONE_ANONYMOUS` が
   入っていることを確認する）

## 2. 合言葉について（設定は不要）

合言葉の設定はデプロイ時には不要。**各ユーザーが初回接続時に自分で決める。**
初回の「接続テスト」（init）で、そのスプレッドシートIDと合言葉の
ハッシュがスクリプトプロパティ（`BIND_<スプレッドシートID>`）に
自動で紐づく。以後の push/pull は同じ合言葉でなければ拒否される。

- 合言葉は8文字以上。推測できる文字列は使わないよう、ユーザーに伝える。
- 合言葉を忘れた場合の復旧：スクリプト プロパティを開き、該当する
  `BIND_<スプレッドシートID>` を削除する。次回の接続テスト（init）で
  新しい合言葉で紐づけ直せる。**削除するプロパティを間違えると他の
  ユーザーの紐づけが消える**ので、IDを確認してから行うこと。

## 3. Webアプリとしてデプロイする

1. 右上の「デプロイ」→「新しいデプロイ」を開く。
2. 左上の種類（歯車アイコン）で「ウェブアプリ」を選ぶ。
3. 設定は次の通り:
   - 説明: `SmashStats 同期ブリッジ`（任意）
   - 次のユーザーとして実行: `自分`（＝ブリッジ用アカウント）
   - アクセスできるユーザー: `全員（匿名ユーザーを含む）`
4. 「デプロイ」を押し、権限の確認が出たら許可する。
   （スプレッドシートへのアクセス権限を求められる）
5. 表示される **ウェブアプリの URL（`…/exec` で終わるもの）** を控える。
   これが PWA の「ブリッジURL」になる。

## 4. PWA側で接続する（ユーザー操作）

1. PWAの「設定 → データの置き場所」を開く。
2. ブリッジURLに手順3の URL を貼る。
3. 自分のスプレッドシートのURLを貼る。
   **先に、そのスプレッドシートをブリッジ用アカウントと「編集者」として共有する。**
   共有相手は、手順1でログインしたアカウントのメールアドレス。
4. 合言葉に自分で決めたもの（8文字以上）を入力し、「接続設定を保存」を押す。
   初回はこの合言葉がこのスプレッドシートの鍵になる。忘れないよう控えておく。
5. 「接続テスト」を押す。シート構成と schemaVersion が確認できれば成功。
   初回は10シート（9テーブル＋_meta）が作られ、1行目に列ヘッダーが入る。
6. 「今すぐ同期」を押す。端末内のデータがシートへ上がり、シート側の
   新しい行が端末へ降りてくる。

## 5. 更新するとき

- `Code.gs` を修正したら、再度「デプロイ」→「デプロイを管理」→
  対象のデプロイの鉛筆アイコン →「バージョン: 新しいバージョンを作成」→
  「デプロイ」する。**新しいデプロイを作り直すと URL が変わる**ので、
  必ず既存デプロイのバージョン更新で行うこと。
  （`BIND_<ID>` の紐づけはスクリプトプロパティに残るので、コード更新で
  消えることはない）

## トラブルシューティング

| 表示・症状 | 原因と対処 |
|---|---|
| `FORBIDDEN` | アプリ側の合言葉が違う。端末の合言葉を再入力する。 |
| `PASSPHRASE_TOO_SHORT` | 合言葉が8文字未満。8文字以上で入力する。 |
| `NOT_INITIALIZED` | まだ初期化されていないシートに push/pull しようとした。先に「接続テスト」を実行する。 |
| `SPREADSHEET_NOT_FOUND` | URL/IDが違う。スプレッドシートのURLを貼り直す。 |
| `SPREADSHEET_NOT_SHARED` | ブリッジ用アカウントと共有されていない。共有設定を確認する。 |
| `HEADER_MISMATCH` | シートの列構成が想定と違う。既存のシートを流用せず、接続テスト（init）で作ったシートを使う。 |
| `SHEET_NOT_FOUND` | シートが無い。接続テスト（init）を先に実行する。 |
| `LOCKED` | 他の同期が実行中。少し待ってから再度同期する。 |
| 同期が遅い・途中で止まる | 1万行超の初回同期は分割される。残りは次回同期で送られる。 |
| CORS（接続できない） | PWAは `Content-Type: text/plain` で送っている。ブリッジURLが `/exec` で終わっているか確認する。 |

## セキュリティの考え方

- ブリッジは「呼び出し側が指定したスプレッドシートIDだけ」を開く。
  ただし実行アカウント（デプロイしたアカウント）が開ける範囲に限る。
- スプレッドシートごとに合言葉のハッシュを紐づけて保存し、合言葉が
  合わない呼び出しはすべて拒否される。合言葉そのものは保存しないため、
  漏れてもハッシュからは復元できない。合言葉を変えたい場合は
  手順2の復旧方法で紐づけを消し、次回 init で紐づけ直す。
- 試合データ・氏名はブリッジに保存しない。ログにも残さないこと。
