設計書: `~/workspace/smashstats-iphone-web/DESIGN.md`（§4・§8・§15 Phase 1の範囲だけ実装）

## 動作環境

- iPhone Safariで開き、共有ボタン →「ホーム画面に追加」して使う（PWA）。
- オフラインで動く。初回はオンラインで開いてService Workerを登録させること。
- ローカル確認: `python3 -m http.server 8000` でこのフォルダを配信し、`http://localhost:8000/index.html` を開く。

## Phase 1で入っているもの

- 5タブ（ホーム / 試合 / 登録 / 分析 / 用具）＋設定。下部タブバー、390px基準、Safe Area対応。
- IndexedDB（DB名 `smashstats-web`）: 9ストア（players / matches / gears / gear_maintenances / venues / opponent_profiles / opponent_custom_items / focuses / notes）＋ `_outbox` ＋ `_meta`。`scoresJson` は `SetScore[]` のJSON文字列のまま保持。
- 選手管理（追加・切替）。無料版は1名まで。
- 試合の登録・一覧・編集・削除。セットの動的行追加（スコア＋タイブレーク＋RET/WO/DEF）、モメンタム、団体戦、勝敗の自動判定。無料版は当月5試合まで。一覧は日付降順＋検索（相手名・大会名）＋勝敗フィルタ。
- ホーム: 現在のフォーカス、直近3試合、件数サマリ、未同期件数。
- 分析（最小限）: 総試合数・勝率・月別勝率・サーフェス別勝率。
- 用具（最小限）: ギア一覧・追加・編集・削除、張り替え日と経過日数・張り替え後試合数、張り替え記録。
- 設定: 言語切替（JA/EN、辞書オブジェクト方式）、テーマ切替（スタンダード / ミントペール）、JSON全量書き出し・取り込み（Android版と同じキー名）、デモデータ投入・削除、Pro・ライセンス（Phase 4）、データの置き場所（Phase 2予定の表示のみ）。
- 競技別スコア計算は純粋関数 `calcGameProgress` / `decideWinner` に集約（バドミントン21点・30点キャップ、テニス4ポイント/タイブレーク、卓球11点、ピックルボール11点）。ポイント入力シートからも呼ぶ。
- すべての書き込みは `_outbox` にも1件積む（Phase 2の同期が消費する）。
- `navigator.storage.persist()` を起動時に呼ぶ。ホーム画面追加の案内バナーを表示する。

## Phase 2で入ったもの — スプレッドシート同期

共通Apps Script（`../apps-script/Code.gs`）をブリッジにして、自分の
Google スプレッドシート1冊と同期する。端末内 IndexedDB が普段の正で、
スプレッドシートが正本。競合は最終書き込み勝ち（`updatedAt` 比較）。

### 接続手順（初回）

1. ブリッジをデプロイする（`../apps-script/DEPLOY.md` 参照）。
   Webアプリの URL（`…/exec`）を控える。
2. 自分のスプレッドシートを用意し、**ブリッジ用アカウントと「編集者」として共有**する。
   共有していないとブリッジは `SPREADSHEET_NOT_SHARED` を返す。
3. アプリの「設定 → データの置き場所」を開く。
4. ブリッジURL、スプレッドシートのURL、自分で決めた合言葉（8文字以上）を入力し、
   「保存」を押す。初回接続時にその合言葉がこのスプレッドシートの鍵として登録される。
   合言葉はこの端末内にだけ保存され、書き出し・同期の対象にはならない。
5. 「接続テスト」を押す。10シート（9テーブル＋`_meta`）が作られ、
   1行目に列ヘッダーが入る。既存シートの列構成が違う場合は上書きせずエラーになる。
6. 「今すぐ同期」を押す。端末内の未同期の変更がシートへ上がり、
   シート側の新しい行が端末へ降りてくる。

### 同期ボタン

- **今すぐ同期**: 未同期の変更を送信（push）→ シートの全行を取得して取り込み（pull）。
  起動時にも設定済み・オンラインなら自動で同じことをする（失敗しても黙って残す）。
- **復元する**: 確認ダイアログのあと同期と同じ流れでシートから取り込む。
  ローカルを丸ごと上書きするのではなく、`updatedAt` 比較でマージする。
  端末内のデータが消えた状態で押すと、シートの内容がそのまま戻る。
- **接続テスト**: `init` を呼んでシート構成と schemaVersion（16）を確認する。

### 同期の状態表示

設定画面の「データの置き場所」に表示される。

- 最終同期: 最後に同期が成功した日時
- 未同期の変更: まだシートへ送っていない変更の件数（ホームにも表示される）
- 競合: シート側が新しくて採用されなかった件数（累計）
- 直近のエラー: 同期に失敗したときの理由
- 同期中は「送信中…（N秒）」「受信中…（N秒）」と段階と経過秒を表示する。
  ブリッジ1回あたり60秒応答がなければ打ち切ってエラーを表示する
  （Apps Script のリダイレクト経由は遅く、無期限に待つとボタンが
  効かないように見えるため）。

### 同期しないもの

- 写真・動画の本体（参照文字列だけ同期する）
- 端末の設定（テーマ・言語）、ライセンスキー、合言葉

## Phase 4で入ったもの — Stripe買い切り・ライセンス

PWA 側（`index.html`）とライセンスサーバー（`../license-worker/`、Cloudflare Workers＋D1）。

### PWA 側

- 設定 →「Pro・ライセンス」カード: 無料枠の使用量（今月の試合 n/5・選手 n/1）、
  Pro の状態（利用中の端末 n/2・最終確認日）、購入・ライセンス入力・復元・解除、
  ライセンスサーバーURLの入力欄。
- 購入: 「Proにする（買い切り）」→ ライセンスサーバーに Checkout セッション作成を
  頼み、返された Stripe Checkout の URL へ遷移する。決済完了でアプリに
  `?license_session=…` で戻り、ライセンスキーを発行して1回だけ表示する
  （コピー可。端末内に保存されるのはキーの SHA-256 ハッシュだけ）。
- ライセンスキー入力: キーをハッシュ化してサーバーに問い合わせ、有効なら Pro 解放。
  1ライセンス＝端末2台まで。3台目は拒否される。
- 復元: 購入メールアドレスを入れるとキーの末尾4文字のヒントが表示される。
  キーの全文は表示しない。
- 解除: この端末の Pro を解除し、サーバー側の端末登録も空ける（2台枠が空く）。
- Pro の再確認: 起動時に最終確認から7日以上たっていたら、ハッシュで静かに再確認する。
  サーバーから無効化・台数超過の確定応答が来たときだけ Pro を解除する。
  ネットワークの失敗では解除しない（過去のデータは読める・書き出せる）。
- 無料枠の制限（選手1名・月5試合）は Pro で解除される。CSV取り込みの上限も同じ。
- 価格は未決定のため `LICENSE_PRICE_JPY` は `null` のまま。未設定の間は購入ボタンが
  「価格は近日公開」と表示される。価格が決まったらここ（表示用）と Worker 側の
  `STRIPE_PRICE_JPY` / `STRIPE_PRICE_ID`（請求額）に同じ金額を入れる。
- `LICENSE_WORKER_URL` は空のまま（デプロイ後に Worker の URL を入れる）。
  設定画面の「ライセンスサーバーURL」欄からも入力できる。

### ライセンスサーバー（`../license-worker/`）

- `src/index.js`（依存なし）＋ `schema.sql` ＋ `wrangler.toml` ＋ `DEPLOY.md`。
- エンドポイント: `/api/health`、`/api/create-checkout`（プロモコード対応。
  Stripe クーポンは決済時に自動作成）、`/api/claim`（決済確認・初回のみキー発行）、
  `/api/verify`（キー or ハッシュ＋端末）、`/api/restore`（ヒントのみ）、
  `/api/unbind`（端末登録の解除）、`/api/webhook`（署名検証・冪等性あり。
  返金・チャージバックでキーを無効化、dispute 勝訴で復活）、
  `/api/admin/reissue`（運用者専用のキー再発行）。
- 保存するのはキーのハッシュ・購入メールアドレス・端末ID・決済セッションIDだけ。
  試合データ・選手名は通らない。デプロイは `../license-worker/DEPLOY.md` を参照
  （D1作成 → スキーマ → Worker → シークレット → Webhook → テストモードで通す）。

## 公開手順（GitHub Pages）

公開作業自体はこのフェーズでは行わない。承認後に行う手順のメモ:

1. リポジトリ（例: `mugiodas.github.io` 配下の新規リポジトリ、または既存リポジトリのサブディレクトリ）に `app/` の中身を置く。
2. GitHub Pagesの公開元をそのディレクトリに設定する。
3. 公開URL（例: `https://mugiodas.github.io/smashstats-web/`）をiPhone Safariで開き、ホーム画面に追加する。
4. 公開後の確認: 5タブの表示、試合登録→リロード後の残存、ホーム画面追加後の起動、オフライン（機内モード）での起動・登録。

## 既知の制限・注意

- Service Workerは `http(s)` でしか登録できない。`file://` で開いた場合はSWなしで動く（IndexedDBは動く）。
- 写真・動画は本体を保存しない。`photoPath` / `videoPathOrUrl` は参照文字列のみ。
- 会場（venues）・対戦相手（opponent_profiles）・ノート（notes）のストアはDBに用意済みだが、Phase 1の画面はまだない（JSON取り込み・書き出しでは扱える）。
- 無料枠の判定は端末内のみ（ライセンス認証はPhase 4）。
